# 设计说明

## 第一版目标

第一版不是“网盘替代品”，而是申请材料的控制台。它先解决三件事：最近交什么、当前缺什么、下一步由谁负责。

## 信息结构

1. **总览**：最紧急节点、官方日期覆盖率、整体材料进度、本周行动。
2. **13 个项目**：搜索和地区筛选；进入项目后查看材料要求、奖学金机制、官网和状态。
3. **通用材料**：只记录材料主档和私密目录，不展示真实文件。
4. **推荐信分配**：记录数量规则、老师侧重点和覆盖项目，防止内容冲突。
5. **协作与隐私**：明确无后端条件下的同步方式与不能上传的敏感信息。

## 文件架构

```text
00_admin            项目元数据、截止日期、账号状态（不存密码）
01_profile          CV、个人信息表、经历素材库
02_academic         成绩单、评分说明、排名、在读/学位证明
03_tests            IELTS、GRE、送分记录
04_recommendations  推荐人 brief 与学校清单
05_projects         每个项目的文书、材料清单、提交版
06_scholarships     奖学金题目、申请与结果
07_submissions      提交回执、付款收据、portal 截图
99_archive          历史版本
```

每个项目沿用 `P01`–`P13` 固定编号。文书同时保留 `editable` 和 `submitted`；已提交版本不覆盖。

## 为什么暂时不做后端

账号、共享文件和推荐信都会显著提高权限与数据泄漏风险。当前申请季最需要的是一套立刻可用的统一视图，因此先把状态与材料要求跑顺。多人实时编辑、评论、通知和权限审计放到第二阶段。

## 通用版演进

通用版将“项目”抽象为留学、保研、奖学金三类，共用材料主档、截止日期、负责人、文件版本和提交回执。届时再增加用户角色（学生/中介/推荐人）、权限、评论、变更记录和自动提醒。
