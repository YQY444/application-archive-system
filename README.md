# 2027 Fall 申请归档台

一个纯前端的留学申请工作台，当前内置杨琪勇的 13 个 2027 Fall 项目，也可以继续添加任意院校项目。项目数据、材料文件和网申账户信息只保存在使用者自己的浏览器中。

## 当前能力

- 新增、编辑和删除申请项目
- 集中记录学校、专业、轮次、截止日期和网申链接
- 每个项目的文书、CV、推荐信、成绩单、GRE/WES 等逐项要求与状态
- 直接上传、预览和下载申请文件；文件保存在浏览器 IndexedDB
- 在当前浏览器中保存网申账户名与密码，不写入代码仓库或工作区备份
- 导出或导入包含项目数据与材料文件的 JSON 备份，用于无后端协作
- GitHub Pages 静态构建与自动部署工作流

## 隐私边界

代码仓库不会保存浏览器中的工作区数据。不要手动把以下内容提交到 GitHub：

- 护照、身份证、证件照
- 成绩单、排名证明、在读或学位证明
- IELTS/GRE 成绩报告、WES reference
- 推荐信正文、推荐人私信
- Portal 账号、密码、申请号、付款收据

导出的工作区备份包含已上传的申请文件，应只通过权限受控的私密渠道传递。账号密码不会进入备份；如需与中介共享，建议使用密码管理器。

## 本地运行

```bash
pnpm install
pnpm run dev
```

生产构建：

```bash
pnpm run build
```

GitHub Pages 静态构建：

```bash
pnpm run build:pages
```

输出目录为 `pages-dist/`。

## 初始项目数据

首次打开时，`app/data.ts` 中的 13 个项目会作为初始数据载入。之后的修改保存在浏览器中。更新初始截止日期时，同时维护：

- `deadline`：界面显示文本
- `deadlineSort`：`YYYY-MM-DD` 排序值
- `verified`：只有 2027 官方页面明确发布后才能设为 `true`
- `applicationUrl` / `scholarshipUrl`：只使用学校官方页面

## GitHub Pages

仓库已包含 `.github/workflows/deploy-pages.yml`。在 GitHub 仓库 Settings → Pages 中把 Source 设为 **GitHub Actions** 后，推送到 `main` 即会自动构建。

建议先保持仓库私有。若账户套餐不支持私有 Pages，需要决定：升级套餐，或另建一个只含更少个人信息的公开展示仓库。

## 无后端协作方式

工作区不会自动在两台设备间同步。任一方更新后可点“导出备份”，将 JSON 通过私密渠道发给另一方导入。导入会包含材料文件，但不包含网申账号密码。需要实时共同编辑时，仍需接入受控后端或私密云盘。
